# P0 测试用例（R00–R03 修复验收 · T01 扩展）

> 依据：开发级 PRD v0.2 §5.1（R00/R03）、§5.2 N1、§8.3 T01；评审版 v3.1 §6 风险红线。
> 执行机：**xujinya（Win10 / PowerShell 5.1 + Win11 / PS7 真机）+ mac 真机**——本用例集必须在真机执行，沙箱通过不算数。
> 关联缺陷：2026-10-03 评审复现（asp.ps1 L487 `Copy-Item -Recurse -Force` 无存在检查；asp.sh L323 裸 `cp -R` 无备份）。每例保存 commit、包版本、输入夹具、预期、实际、失败截图或脱敏日志；全过才解除"双击周更"宣传冻结。

## TC-R00-01 同版本二次安装（已存在技能目录 · Windows 嵌套）

- **前置**：Windows 真机已用同一 asp 版本装过 base 包（技能目录已存在）。
- **步骤**：再次执行 `setup.bat` / `asp.ps1 install`（同版本）。
- **期望**：零嵌套（不产生 `技能名/技能名/` 目录）；已存在目录不被静默覆盖；报告逐技能 PASS/WARN/FAIL 且给出恢复入口。
- **依据**：PRD R00「同版本二次安装零嵌套」。

## TC-R00-02 旧→新周更（用户改过顶层 SKILL.md）

- **前置**：已装 v0.13.0 包，用户手改某技能顶层 `SKILL.md`（加一行标记注释）。
- **步骤**：源 registry 更新为新版 → 执行 `update.bat`。
- **期望**：顶层 SKILL.md 变为新版；用户改动有备份（`_backup/`）且可恢复；再次更新**无重复**（PRD Given/When/Then 原文）。overlay 机制上线后（P1）个人改动进 overlay。
- **依据**：PRD N1「Given 用户改过顶层技能，When 周更，Then 顶层为新版且个人改动有备份/overlay」。

## TC-R00-03 mac/Linux 覆盖前备份

- **前置**：mac 真机已装包，源更新为新版。
- **步骤**：`./asp.sh update`。
- **期望**：同名技能目录覆盖**前**先备份到 `_backup/`；不出现无备份直接覆盖。
- **依据**：PRD R00「asp.sh 同名技能覆盖前备份」。

## TC-R00-04 历史嵌套目录安全迁移

- **前置**：目录中存在历史缺陷产生的 `技能名/技能名/` 嵌套结构；其中一层混入**用户自建文件**。
- **步骤**：运行修复后的安装器（含识别→备份→迁移逻辑）。
- **期望**：仅当确认为旧安装器产物、备份完成、**且无未知用户文件**时才清理合并；检测到未知文件时**隔离并报告**，绝不递归删除未知目录；全程不丢文件。
- **依据**：PRD N1「历史 技能名/技能名/ 仅在确认为旧安装器产物、备份完成且无未知用户文件时清理；否则隔离并报告，绝不递归删未知目录」。

## TC-R00-05 未知文件与符号链接

- **前置**：技能目录/目标目录内放置符号链接（指向外部）与随机未知文件。
- **步骤**：安装 / update / （后续 vault 命令）。
- **期望**：不跟随符号链接写入、不做路径穿越；未知文件保留并报告，不删除。
- **依据**：PRD §5.8「检测符号链接/路径穿越，不递归删来源不明目录」。

## TC-R00-06 平台矩阵复核

- **矩阵**：Win10 + PowerShell 5.1（系统自带）、Win11 + PS7、mac 真机；Linux 可列缺口不强制本轮。
- **期望**：TC-R00-01～05 在每个必测组合结果一致；差异如实记录为缺口，不写"全平台通过"。
- **依据**：PRD T01「Win10/PowerShell 5.1、Win11/PS7、mac、Linux 的可测组合列出实际结果与缺口」。

## TC-R03-01 doctor 嵌套检测与加载口径

- **前置**：一台机器装过包（含一处人为构造的历史嵌套）。
- **步骤**：`asp doctor`。
- **期望**：报告含嵌套检测项；对每目标区分「写入 / 加载 / 任务遵从」三层，doctor 的 MCP `initialize` 握手**不得**计作"已加载/可用"证据；无 Agent 时给官网链接与重跑提示，不代装。
- **依据**：PRD R03、§5.7 三层证据口径。

## TC-R01-01 export 凭证拦截（R01 落地后追加执行）

- **前置**：MCP 配置含测试用假 token（如 `sk-test-...`）。
- **步骤**：`asp export`（含中断恢复场景）。
- **期望**：产物与日志均无原值（仅占位符）；对最终内容 lint，报警即中止、不留半成品、不自动推 git；GitHub 通道在 R01 通过前保持文档冻结（见 MIGRATE.md 顶部口径）。
- **依据**：PRD N2、R01、D18。

# 防盗版与授权策略（含每周版本化安装代码方案）

> 2026-09-30 定稿 · 关联：HOSTING.md（registry 双源）、shop-listing.md（商品页）、家族A执行方案 v1.4
> 前提共识：skills 是明文 markdown（agent 必须直接读），**本地内容放弃防护，唯一可控咽喉是 registry 更新通道**。策略目标不是"防死转卖"，而是让转卖**无利可图 + 可溯源 + 可转化为分销**。

## 一、用户协议层（核心决策，2026-09-30）

**"转售即分销"条款**——不禁止转售，而是把它变成合法赚佣金的通道：

> EULA §授权与转售（草案）
> 1. 本包为个人授权：可安装于本人任意设备与任意 agent，**不可再分发、不可转让、不可用于衍生付费服务**。
> 2. **转售通道**：如需向他人提供本包（含转卖、拼团、代装服务），须先申请成为官方分销者（群内/表单申请，即时开通）。分销者通过专属推荐链接/推荐码成交的订单，获得 **30% 返佣**；未经申请的转售视为违约，官方有权停止其更新服务并溯源追责。
> 3. 更新服务与购买凭证绑定；转卖旧版本不影响正版更新权益。

条款展示位置：商品页（购买前可见）＋ 安装完成报告尾部 ＋ zip 内 EULA.txt。
配套：分销申请表单（腾讯问卷/群接龙起步）＋ 订单-推荐码对照表（Excel 起步，规模化后进 OSS 侧）。

**法律层配套（W3 上架前）**：
- 自产 skills 批量做**作品著作权登记**（约 300 元/批）——平台投诉（闲鱼/淘宝/GitHub）下架效率的关键筹码
- MIT/Apache 改造部分本就授权再分发（义务仅保留版权声明，THIRD-PARTY-NOTICES.md 已合规）——**商品价值叙事只落在自产内容**，这部分法律上不防、也不用防

## 二、技术层：每周版本化安装代码（方案定稿）

### 目标与边界

每周生成不同的安装代码/入口，对应当周内容版本。**它防不了"转卖当周静态包"**（转卖者转的就是那份 zip），其真实作用是三件事：

1. **版本卫生**：旧代码只装到旧内容，装完即提示"本周已有新版"——转卖包自然贬值
2. **溯源**：每周入口在生成时可注入渠道/买家标识，倒卖源可定位到订单
3. **过期自提示**：N 周未更新的安装体主动引导 update，把"死包"拉回更新流

### 三层结构（安装器与内容分离，避免用户认知负担）

| 层 | 变化频率 | 形态 | 说明 |
|---|---|---|---|
| 安装器 | **永久稳定** | `setup.bat` / `asp.ps1`（不变） | 用户认的是它；每周换安装器会让用户困惑"上周的还能用吗" |
| 内容版本 | 每周 | `registry/index.json` 的 `version` + 新增 `period` 字段 | 现有周更流水线已覆盖 80% |
| 当周安装入口 | 每周生成 | `dist/weekly/<period>/` 下的当周 zip + 入口链接 | **v1**：版本化短链（如 `asp.example.com/w40` 重定向当周 zip）；**v2**：按订单生成**OSS 签名 URL**（每单每周一个专属链接，有效期 7 天，转卖链接=可溯源+自动失效） |

### 实现落点（挂在现有流水线上，预计 0.5-1 天）

1. **`registry/index.json`**（schema 0.2 → 0.3）：
   - 顶层加 `"period": "2026W40"`（ISO 周号）与 `"min_updater": "0.5"`
   - 每包条目加 `"period"`（该包最近发版周）
2. **`scripts/build-release.ps1` 扩展**（第⑤步）：
   - 发版时输出到 `dist/weekly/<period>/`（zip + `.sha256` + `entry.txt` 当周安装说明）
   - 自动把 `period` 写入 index.json
   - （可选参数 `-BuyerId xxx`）生成时在 zip 内写 `_meta/buyer.txt` 水印——**按订单出包时用**，公开渠道不带
3. **`asp.ps1` update 过期提示**：
   - 更新检查时对比本地 `_state.json` 的 period 与 index.json 的 period：差 ≥2 周则安装报告与 update 输出加提示"内容已落后 N 周，本周最新版已发布（w42）"——非强制，只引导
4. **v2（等首批真实付费用户后做，勿提前）**：OSS 侧按订单签名 URL——发版脚本读订单表批量生成当周专属链接，推送渠道=更新群。这是"每周不同代码"的真防护形态：链接与订单绑定、7 天过期、拉取异常可监控（同凭证多 IP 告警）

### 不做清单

- ❌ DRM / 加壳 / 安装时 license 强校验——对明文 markdown 无效，且破坏"双击即用"核心体验
- ❌ 每周更换安装器本体——认知负担 > 收益
- ❌ 0 付费用户阶段上 v2 签名体系——先验证有人买

## 四、底线判断

转卖必然发生，接受它。护城河 = 自产内容占比 + 周更速度 + 更新通道鉴权（v2）+ 私域服务 + lite 占位。
每周版本化代码的本质是**版本管理与溯源基础设施**，不是加密——别在这上面过度投入。

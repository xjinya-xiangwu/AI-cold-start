# 文档查新（Fresh Docs）

## 触发场景

- "Next.js 15 里 params 为什么是 Promise？"
- "这个报错在新版本里还这样处理吗？"
- "某某平台的审核规则/开放接口现在是什么要求？"
- "从 v2 迁移到 v3 要改什么？"
- 任何你训练截止日期之后可能发生变化的库、框架、平台、SDK、CLI 用法

不触发（可直接答但声明依据）：语言基础语法、数学、稳定多年的概念——回答时注明"基于训练知识"。

## 为什么需要

模型对库/平台的知识停在训练截止日，而生态月月在变：API 改签名、配置换格式、平台改规则。凭记忆回答这类问题 = 高概率给出已废弃的用法。查一次官方文档的成本，远低于用户按错误答案返工。

## 工作流

### 第一步：判定需要查新

满足任一条即必须查：① 明确涉及版本/迁移/最新；② 该库半年内可能发过大版本；③ 平台规则类（审核/合规/接口配额，天然时效）；④ 用户给的报错信息含版本号。判定不了就查——查的成本低，错的成本高。

### 第二步：检索三步法

1. **搜索**（有 websearch 类工具时）：`<关键词> + official docs / documentation / changelog`，版本号已知就带上版本号
2. **选官方域**：从结果中优先选——`docs.<产品>.com/io/dev`、产品官网、官方 GitHub 仓（含 README/docs 目录）；**跳过**二手教程站、聚合站、翻译站（可当线索，不当依据）
3. **定向抓取**（webfetch 类工具）：抓具体文档页，不抓首页——搜索结果的 URL 已经是深链就直取；是首页就先找导航里的目标页面再抓

无搜索工具时（部分环境只开放 fetch）：直接 fetch 你已知的目标官方域路径（训练知识里的官方域名通常仍有效），404 再降级。

### 第三步：输出口径（三条硬规则）

1. **结论 + 版本锚**：答案必须带适用版本号或文档更新日期；两样都拿不到，明写"版本未验证"
2. **来源 URL**：给出你实际抓取的官方页地址
3. **多版本分列**：问法未指明版本且各版本行为不同时，按版本分列，不混写

### 降级链（按环境能力自动降）

```
已装 context7 类文档 MCP → 优先用（结构化切片质量更高）
→ 内置 websearch + webfetch → 走三步法
→ 仅有 webfetch → 直取已知官方域
→ 无任何 web 工具 → 答前明示"以下基于训练知识（截止 <日期>），可能过期，请以 <官方域> 为准"
```

## 反模式

- ❌ 用搜索结果摘要直接当结论——摘要会截断条件语句，必须 fetch 到原文页
- ❌ 引用二手教程站当权威依据（教程常滞后一到两个版本）
- ❌ 混写多版本行为而不标注适用版本
- ❌ "最新版本应该是…"这类无来源的猜测句式

# OKR 制定

## 触发场景

- "帮我写下季度的 OKR"
- "这是我们团队的 OKR，帮我看看质量"
- "老板让我把目标拆成 KR"

## 工作流

### 第一步：Objective（目标）三条铁律

1. **定性挑战，不是数字**："把新用户第一周留存做起来" ✅；"留存达到 45%" ❌（数字属于 KR）
2. **有方向感**：能让团队看懂"赢"长什么样；看完无感的目标重写
3. **一周期 3 个以内**：超过 3 个 = 没有重点，砍到痛为止

反模式检查：
- 把待办清单当目标（"完成 X 系统升级"是任务不是目标——升级本身不产生价值，问一句"升级之后什么会变好"）
- 把口号当目标（"打造极致体验"——无法判断输赢）

### 第二步：Key Results（关键结果）四条铁律

1. **可验证**：周期结束时能客观回答"达没达成"，不靠各自解读
2. **可归因**：KR 的变化主要来自团队的行动，而非大盘/季节（大盘涨 50% 时"营收 +30%"不算挑战）
3. **数量 3-4 条/目标**：覆盖"结果 + 质量护栏"（如"新增付费 1000 家 + 退款率 ≤3%"，防止只冲量）
4. **有基线**：写清当前值 → 目标值（"从 22% 提到 30%"），没有基线的 KR 无法校准置信度

**过程指标不进 KR**（上线数、访谈数是任务，不是结果）；确需过程管理放进行动清单单独跟踪。

### 第三步：置信度校准

每条 KR 标注**预估达成概率**，健康区间 **60%-70%**：

- >85%：太保守，不是目标 是待办——上调或换更难的杠杆
- <40%：赌博，团队会放弃——拆出中间里程碑或换 KR
- 校准后整体偏高的组合：通常说明目标没有挑战性，回去重写 O

### 第四步：配套机制（缺了 OKR 就是墙上的字）

- **周检节奏**：每周 10 分钟过进度（红/黄/绿三色），只讨论变红的原因
- **评分口径**：周期末 0-1 分自评，0.6-0.7 = 健康；1.0 说明定低了
- **红线**：OKR 不直接挂钩绩效奖金——挂钩那天起，所有 KR 都会变成保守的待办

## 输出规范

- 输出结构：3 个 O，每个带 3-4 条 KR（基线→目标值 + 置信度 + 一句话为什么是这条杠杆）
- 评审他人 OKR 时逐条对照铁律与反模式清单，给出"改写建议"而非只打分
- 附周检模板（KR / 本周进度色 / 变红原因 / 需要的帮助）

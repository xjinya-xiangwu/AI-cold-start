# Mermaid 产品文档图

## 触发场景

- "PRD 里加一张流程图" / "把这个流程画出来"
- "画个状态机 / 时序图" / "这张图 mermaid 能画吗"

## 工作流

### 第一步：选图型（按表达对象选，一张图只回答一个问题）

| 表达对象 | 图型 | 典型场景 |
|---|---|---|
| 流程步骤与分支 | flowchart | 业务流程、功能逻辑、审批链 |
| 对象状态流转 | stateDiagram-v2 | 订单状态、工单状态、任务生命周期 |
| 参与者交互顺序 | sequenceDiagram | 客户端-服务端调用、多系统协作 |
| 计划与时间 | gantt | 里程碑排期、发版节奏 |
| 实体关系 | erDiagram | 数据模型、后台字段设计 |
| 分类与层级 | mindmap | 需求拆解、功能架构概览 |

- 拿不准就用 flowchart（表达力最广）；状态超过 4 个且互相转换的，用 stateDiagram-v2

### 第二步：语法规范（照写不踩坑）

- 节点文字含中文、括号、标点时一律加引号：`A["用户下单"]`——不加引号是渲染失败的头号原因
- flowchart 方向显式声明：`flowchart TD`（上下）或 `flowchart LR`（左右）；超过 8 步用 TD，横向对比场景用 LR
- 分支条件写在箭头标签里：`-->|是|`；判断节点用菱形 `{"是否已登录"}`
- 子图 `subgraph` 表达阶段泳道；嵌套不超过一层，需要多层说明流程该拆图
- 样式克制：默认配色即可，只给"当前聚焦节点"或异常路径上色——全图彩色等于没有颜色

### 第三步：可读性检查（渲染通过 ≠ 图能用）

- 节点 ≤15 个；超了拆两张图，或先给概览图再给局部图
- 每个节点 ≤15 字，动词 + 宾语（"审核订单"），不写完整句子
- 箭头不交叉成毛线团：布线乱通常是层次没想清，先重画骨架再加细节
- 图前后配一句图注说明"这张图表达什么"——图不解释自己

### 第四步：按环境给交付形态

- 支持 markdown 渲染的 agent / 编辑器：直接输出 ```mermaid 代码块
- 不支持渲染的环境：同时给代码块 + 文字版流程（步骤 1→2→…），并提示可粘贴到 GitHub / 飞书文档 / Typora 等支持 mermaid 的地方查看
- 需要 PNG/SVG 文件资产时，提示可选方案（mermaid-cli，需 node 环境，见 optional-mcp 工具链说明）

## 判断基准

- 图是思维的显影，不是装饰：写不出图的流程，通常说明流程本身没想清，先回去补逻辑
- PRD 必配图的三处：核心业务流程、状态流转、异常/边界路径——正文说不清的用图兜底
- mermaid 代码是文本：可 diff、可版本管理；改图先改代码，不要截图

## 输出规范

- 输出：一句图注 + mermaid 代码块（必要场合附文字版流程）
- 与 prd-drafting 衔接：12 章模板中"业务流程 / 状态 / 异常流"章节的配图从这里取材

# 假设审计

## 触发场景

- "这份 PRD 帮我看看有没有坑"
- "方案要评审了，帮我查一遍"
- "这个计划你觉得靠谱吗"

## 工作流

### 第一步：把假设挖出来（显式 + 隐式）

方案里每句话背后都站着假设。逐段扫描，四类高频藏身处：

| 藏身处 | 典型隐含假设 |
|---|---|
| 用户描述 | "用户会主动打开"（假设有入口动机）、"用户看得懂"（假设认知基础） |
| 数据引用 | "市场有 X 亿"（口径假设）、"竞品用户 = 我们用户"（同质假设） |
| 依赖说明 | "技术说能做"（承诺粒度假设）、"下月接口就绪"（排期假设） |
| 效果预期 | "上线后留存提升"（因果假设：提升真来自这个功能？） |

挖法：对每句陈述问"**这句话成立需要什么为真？**"——答案就是假设。

### 第二步：假设登记表

```
A#  假设内容  类型(市场/技术/用户/组织/资源)  依据(数据/类比/直觉)  翻车代价  不确定性  验证方式
```

- 依据三档：**数据**（有来源）/ **类比**（有参照案例）/ **直觉**（无）——直觉依据的假设自动升级不确定性
- 翻车代价：高（方向错误/资损）/ 中（返工延期）/ 低（体验瑕疵）
- 不确定性：高（从未验证）/ 中（有间接证据）/ 低（多次验证过）

### 第三步：排验证优先级（风险 = 代价 × 不确定性）

- **高危区**（高代价 × 高不确定性）：必须在方案通过前验证——设计专门验证动作（访谈/数据查询/POC）
- **观察区**（高代价 × 低不确定性 或 低代价 × 高不确定性）：上线后设监控信号，不阻塞
- **接受区**（低代价 × 低不确定性）：记录在案即可，不投入

### 第四步：输出与跟进

- 高危区假设逐条给出：验证动作 + 预计成本 + 谁来做 + 最晚什么时间点前要有结论
- 验证结论回填登记表：成立 → 降级；不成立 → 触发方案修改（改哪段直接标出来）

## 判断基准

- 一个方案挖不出 ≥5 个假设，说明挖得不够深——回去再问一轮"这句话成立需要什么为真"
- 全是低危假设的审计没有意义：说明方案保守或挖掘太浅，二选一要确认
- 审计对象是方案不是人：不评价写方案的人，只登记假设

## 输出规范

- 主交付物是假设登记表（全部字段填满），不是一段"整体风险可控"的散文
- 高危区假设单列"验证清单"，可直接转为项目待办
- 与 prd-review 的分工：prd-review 查结构与规范，本 skill 查假设与风险，送审前两个都跑

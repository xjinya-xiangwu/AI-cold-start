# 数据洞察与归因分析

## 触发场景

- "这个月留存为什么掉了？"
- "帮我把这张表分析一下"
- "周报里的数据部分帮我写"

## 工作流

### 第一步：数字三问（不通过就不进入分析）

对每个关键数字先核：

1. **口径**：怎么统计的？分母是谁？统计周期？过滤条件？（如"活跃"是打开还是核心动作）
2. **基线**：和什么比？环比/同比/和目标比——没有对比的数字不是信息
3. **稳定**：是小样本抖动还是真变化？（日样本 <1000 的波动慎判趋势）

口径不清时先向用户确认，确认不了的在结论中降级表述。

### 第二步：归因下钻（维度拆解）

```
总量变化 → 按维度逐层拆：渠道 / 新老 / 平台 / 客群分层
        → 找出"贡献了大部分变化"的 1-2 个维度（贡献度分解）
        → 对该维度再问"为什么"：内部改动（发版/价格/运营动作）对齐时间线
```

- 优先找**结构性解释**（某细分群体/某渠道变了），不满足于"整体涨跌"
- 把同期所有产品改动和外部事件列成时间线，与数据拐点对齐——相关性对上了才值得深挖

### 第三步：生成并收敛假设

列出 2-4 个候选解释，逐个标注：证据强度（强/弱/无）+ 可验证路径（看哪个数据能证实/证伪）。证据弱的假设不进结论，进"待验证"。

### 第四步：结论叙事（金字塔，结论先行）

```
结论（一句话，带数字和方向）
├─ 支撑 1：核心数据 + 对比基线
├─ 支撑 2：结构拆解发现
└─ 不确定项：还解释不了的部分 + 建议的下一步验证
```

**图表选择基准**：趋势用折线 / 构成用堆叠（不超过 4 层）/ 对比用条形（忌饼图比大小）/ 分布用直方图。每图一个论点，图表标题直接写结论（"安卓端次周留存下滑 3.2pt 是主因"而非"留存趋势图"）。

## 判断基准

- 分析的终点是**行动建议**：每个结论回答"所以要不要做什么"；回答不了的标注"仅监测"
- 区分相关与因果的措辞纪律："与…相关"可以，"导致…"需要实验或强机制证据
- 异常好的结果和异常坏的一样可疑——先查埋点变更和数据管道

## 输出规范

- 结构固定：结论 → 支撑 → 不确定项 → 建议动作（含 owner 建议）
- 每个数字带口径脚注；外部数据带出处
- 周报场景额外做"上周结论回顾"：上次说要看的数据看了吗，验证了没有——闭环不闭环决定周报价值

# 数据指标体系设计

## 触发场景

- "这个功能怎么衡量成功"
- "帮我设计数据看板/指标体系"
- "北极星指标怎么定"
- "老板要看数据，我该给他看什么"

## 核心原则

**没有口径的数字是草稿。** 每个指标必须带四要素：

```
口径 = 定义（怎么算） + 统计周期（多久算一次） + 分母边界（统计谁排除谁） + 数据来源（哪张表哪个埋点）
```

## 工作流

### 第一步：锚定业务目标

指标体系是业务目标的翻译，不从指标出发，从问题出发：

1. 这个产品/功能为谁创造什么价值？
2. 价值发生的时刻是什么行为？（用户真正"成功"的动作）
3. 业务方现在最怕什么数字变坏？

价值发生时刻 ≈ 北极星指标候选（例：知识库产品 = "被采纳的问答数"而非"提问数"）。

### 第二步：三层结构

```
北极星（1 个）：价值的最大化表达，全员可背诵
├── 过程指标（3-5 个）：构成北极星的漏斗或因子，可归因可行动
│    例：北极星=采纳问答数 ← ①提问数 ×②命中率 ×③采纳率
└── 护栏指标（2-4 个）：增长时不能变坏的指标
     例：延迟 P95、投诉率、成本/次、误报引发的人工申诉率
```

常见错误：只有过程指标没有护栏——AI 功能最容易"指标涨了、体验烂了"（如命中率上升但回答质量下降）。

### 第三步：逐指标填写口径卡

```
指标名：__
定义：分子（什么事件）/ 分母（什么范围）
周期：实时 / 日 / 周
去重与排除：去重键；排除内部账号/测试流量/机器人
来源：埋点事件名 或 数据表.字段
已知坑：（如：客户端埋点丢失率约 X%，以服务端为准）
负责人：__
```

### 第四步：自检（AI 产品专项）

1. **成本进了看板吗？** 每次调用成本、日总成本必须有——AI 产品的增长可能是亏损放大器
2. **质量指标独立于参与指标吗？** 点赞/采纳（用户判定质量）与使用时长/次数（参与度）分开，防止互相污染
3. **有对照组设计吗？** 上线指标要能回答"比不上线好多少"
4. **反面行为在测吗？** 重新生成率、采纳后修改率、会话放弃率——AI 产品最诚实的信号常在反面

## 输出规范

- 先给指标树（结构图），确认后再逐个写口径卡
- 数据源不可得时明确标注"[当前无埋点，需新增]"并给出事件设计建议
- 附"看板版式建议"：哪 5 个数字放最上面一排（管理层视图），哪些放详情页（执行层视图）
- 拒绝虚荣指标：注册数、累计用户、总调用量只能放附录，不进北极星候选

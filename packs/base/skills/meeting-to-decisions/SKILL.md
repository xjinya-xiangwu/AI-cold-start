# 会议纪要 → 决议与行动项

## 触发场景

- "这是会议记录，帮我整理成纪要"
- "刚开的评审会，把结论和待办拉出来"
- "把这段群聊讨论总结一下"

## 工作流

### 第一步：通读并分类每段内容

把原始记录里的每条信息归入四类：

1. **决议**：有明确结论且有人认领或拍板
2. **倾向**：有方向但未最终确认（"大家觉得可以"≠ 决议）
3. **行动项**：待办的事
4. **背景/噪音**：过程讨论、与技术无关内容（纪要不收录，除非影响理解）

**"讨论过"与"决定了"的分界**是本 skill 的核心价值：出现"我们决定/就这么定/同意了"才是决议；"下次再对一下/再想想/原则上可以"一律归"倾向"。

### 第二步：决议结构化

每条决议记录四要素：

```
决议 R#：[一句话内容]
依据：[支撑该决议的关键理由/数据]
被否方案：[讨论中否掉的备选 + 否决理由]（没有备选就写"无备选讨论"）
影响范围：[影响哪些模块/团队/计划]
```

保留被否方案的理由：三个月后没人记得为什么选 A 不选 B，届时要么重新吵一遍，要么看这行。

### 第三步：行动项结构化

| # | 行动项 | Owner | 截止 | 验收标准 |
|---|---|---|---|---|

- Owner 缺失时不许写"相关同学跟进"——标注 `[待认领]` 并列入未决
- 验收标准：怎么算做完（"跟进 XX" 不是行动项，"拿到 XX 的书面答复" 才是）
- 原始记录里没有的截止时间标 `[待定]`，不许替人编时间

### 第四步：未决问题清单

每条：问题 + **谁来拍板**（具体人名/角色）+ 期望决议时间。没有拍板人的未决问题就是永久未决。

## 输出规范

- 纪要固定结构：会议信息（时间/参会/主题）→ 决议清单 → 行动项表 → 未决问题 → 原始记录要点存档（可折叠）
- 篇幅纪律：决议+行动项部分控制在半页内；超过说明会没开聚焦，如实输出而非硬压缩
- 归属不明的发言标 `[发言人待确认]`，不猜测署名
- 建议随纪要附"上次会议行动项回顾"栏（如有历史）：已完成/未完成/取消

# vibe coding 方向 · 即用指令（10 条）

> 用法：`< >` 内替换成你的实际内容。与 12 个 skills 配合使用。

## 想清楚（开工前）

1. 我想做一个 <项目描述>。用 spec-driven-development 的五问结构帮我写一份规格：问题、范围（含不做清单）、方案概要、验收标准、风险。不确定的地方先问我。
2. 这是我的实现计划：<粘贴计划>。按 karpathy-guidelines 六条准则逐条检查，指出违反之处和更简单的替代方案。
3. 帮我把这个需求拆成 3-5 个薄切片：每片端到端可用、可独立验证，按风险从高到低排序（风险高的先做）。需求：<描述>

## 实现中

4. 用 TDD 实现这个功能：<功能描述>。先写失败的测试给我看，再写最小实现让测试变绿。测试要测行为，不要测实现细节。
5. 在实现 <功能> 之前，先对照 <框架名+版本> 的官方文档验证这个行为假设：<假设描述>。给出文档出处，文档没写的写个最小脚本实测。
6. 为这个项目建一份 CONSTRAINTS.md 质量合同：覆盖测试/类型/性能/安全四个维度，我没说数字的地方你给合理默认值。
7. 审查你刚生成的这段代码，按五轴（正确性/可读性/架构/安全/性能）自查，把发现的问题按 Critical/Required/Nit 列出来，先修 Critical。

## 收尾

8. 对 <文件/模块> 做一次行为不变的简化重构：先列出复杂度信号和对应的简化动作，我确认后再动手。动手前后跑同一套测试证明等价。
9. 按 OWASP 清单过一遍这段处理 <用户输入/认证/支付> 的代码：<粘贴代码>。按严重度列出位置、攻击向量、修复建议。
10. 把今天的改动整理成原子提交序列：每个 commit 写清做了什么和为什么，并按语义化版本判断这次该升哪个版本号、草拟 release notes。

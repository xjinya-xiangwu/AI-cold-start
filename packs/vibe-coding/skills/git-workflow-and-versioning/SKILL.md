# Git 工作流与版本纪律

Git 是你的安全网：**提交是存档点，分支是沙盒，历史是文档**。AI 时代代码产出越快，越靠版本纪律保持可控、可评审、可回滚。

## 提交纪律

- **原子提交**：一个 commit 只做一件事。混着"重构+新功能+修 bug"的提交无法评审、无法单独回滚。
- **信息写清做了什么和为什么**："Fix bug" 是反模式；"修复订单列表对已删除商品崩溃（遍历前未过滤 deleted 标记）" 才能让人搜历史时看懂。
- 脏工作区拆干净：把混杂改动按逻辑分组成多个原子提交（git add -p 逐块挑），而不是一把梭。
- **提交是存档点**：每完成一个可验证的小目标就提交——回滚的粒度由提交粒度决定。

## 分支纪律

- 分支是沙盒：一个分支一个主题；主题完成即合并/删除，不留"祖传分支"。
- 长期并行多条流时，给分支命名约定（feat/xxx、fix/xxx），并在主干合并后同步 rebase，避免漂移。
- 解冲突前先理解**双方为什么都改了同一处**——盲目选一边会把别人的修复合掉。

## 版本与发布

- **语义化版本**：主版本.次版本.修订号——不兼容变更升主版本、向后兼容的新功能升次版本、纯修复升修订号。
- 发 release 时写 changelog：面向用户写"变化带来什么"，区分内部变更与对外可见变更。
- tag 与 release 对应；回滚就是回到上一个 tag——前提是 tag 打得勤。

## 与 AI 协作的应用

- AI 产出的大段代码：先在分支上验收，再原子化合入主干。
- 每让 AI 改一轮就提交一轮存档——AI 改坏时的回滚粒度取决于你的提交频率。

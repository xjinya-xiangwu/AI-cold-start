# 增量实现：薄切片交付

把变更切成**薄的可验证切片**：每片独立可运行、可演示、可回滚。目标是让每一小时的工作都留下可验证的进展，而不是攒一个大爆炸提交。

## 核心方法：曳光弹（Tracer Bullet）

第一个切片就走**端到端的细线**：从输入到输出贯通一条最细的真实路径（哪怕丑、哪怕硬编码）。这条细线证明了整条链路能跑，后续切片再逐段加粗。

- 反面：先写完数据库层、再写完业务层、再写完 UI 层——最后联调才发现三层根本对不上。
- 正面：第一小时就有"输入 → 处理 → 输出"能跑的最小闭环，之后每片都在真实链路上加厚。

## 切片规则

1. **每片一个可验证目标**：写切片前先说清"这片完成后能用什么方式验证"。
2. **每片独立可用**：合并后系统处于可用状态——半成品逻辑必须藏在未接通的路径里。
3. **片间顺序按风险降序**：最不确定、最可能推翻设计的部分先做（探雷），确定性的体力活放后。
4. **每片收尾三件套**：跑相关测试 → 手动验证关键路径 → 提交（原子 commit，写清这片做了什么）。
5. **发现设计问题立即停**：切片是探雷器——第三片发现第一片的设计错了，回滚重来，不要在错误地基上继续加厚。

## 反模式

- **大爆炸提交**：三天的改动一次 commit——不可评审、不可回滚、不可讨论。
- **横向推进**：先把所有模块的"第一层"写完——集成风险留到最后集中爆发。
- **伪切片**：切片只是按文件机械分割，每片单独都不可运行。

## 与 AI 协作时的应用

- 让 AI 每次只交付一个切片，验收后再下一片——比"一次生成全部代码"的返工率低一个量级。
- 每片的验证方式写进提示（"跑这个命令，预期看到 X"），让 AI 自证而不是自夸。

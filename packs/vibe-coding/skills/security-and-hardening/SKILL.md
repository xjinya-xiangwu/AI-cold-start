# 安全加固：把外部输入当敌意处理

安全不是阶段，是 touching 用户数据、认证、外部系统的每一行代码的约束。三句话纪律：**外部输入即敌意、秘密即神圣、每个授权检查都必须在。**

## 五个必查面

### 1. 输入处理

- 所有外部输入（HTTP 参数/头/body、文件上传、第三方回调）先**校验类型/长度/格式/范围**再使用。
- 注入面逐一核对：SQL（参数化，禁止拼接）、命令（禁 shell 拼接，用参数数组）、路径（规范化后校验在预期目录内）、XSS（输出按上下文编码）。
- 反序列化外部数据 = 执行潜在代码——用安全解析器并禁用未知类型。

### 2. 认证与会话

- 密码用 argon2/bcrypt 存储（盐由算法内置），禁止 MD5/SHA 裸哈希。
- 会话 token 随机（密码学随机源）、HttpOnly + Secure + SameSite、登出即失效。
- 登录/改密/支付加速率限制；错误信息不区分"用户不存在"与"密码错误"。

### 3. 授权（最容易漏的一面）

- 每个 endpoint 显式声明所需角色；**默认拒绝**，白名单放行。
- 对象级授权（IDOR）：访问 id=123 前先验证"当前用户拥有 123"——只查登录不查归属是最常见的洞。
- 管理操作二次确认 + 审计日志。

### 4. 秘密与数据

- 秘密（key/密码/连接串）只进环境变量或密钥服务；**代码/日志/错误信息/版本历史零出现**。
- 日志脱敏：密码、token、身份证号打码后才能写。
- 敏感数据最小化：能不算就不存，能短期就不长期。

### 5. 依赖与供应链

- 新增依赖前查：维护活跃度、已知漏洞（npm audit / pip-audit）、许可兼容、下载量。
- 锁文件进版本库、评审 diff；高危告警分诊而不是无视。
- 陌生 npm/pip 包名先核对拼写（typosquatting）。

## 审计输出格式

按严重度分级列出：**位置（文件:行）/ 漏洞类型 / 攻击向量 / 修复建议 / 参考（OWASP 编号）**。零发现也要明确写"检查了哪些面"。

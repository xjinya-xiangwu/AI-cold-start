# 约束驱动开发：把质量底线写成合同

口头质量标准等于没有。这一技能把项目的质量底线写成**成文合同**（CONSTRAINTS.md），并看守每一次变更不被悄悄降标——AI agent 最擅长的就是"为了让测试变绿"悄悄跳过测试、压低阈值、加忽略标记。

## 第一步：访谈确定维度与阈值

逐个维度问维护者"你在乎吗？在乎的话底线是多少？"——没有数字时给出**合理默认值**：

| 维度 | 默认底线（无偏好时） |
|---|---|
| 测试覆盖 | 核心逻辑 ≥80%，跳过测试需注明原因 |
| 类型检查 | 零新增错误（ignore 注释需在 CONSTRAINTS.md 登记） |
| 性能 | 关键接口 P95 < 500ms / 页面 LCP < 2.5s |
| 安全 | 零已知高危依赖；新增输入处理过校验 |
| 可访问性 | 键盘可完整操作；图片有替代文本 |

## 第二步：成文为 CONSTRAINTS.md

每个约束一行，格式：**维度 / 阈值 / 度量命令 / 违规判据**。示例：

```
覆盖率：核心逻辑 ≥80% ｜ 度量：npm run coverage ｜ 违规：总覆盖下降且无登记豁免
类型：零新增错误 ｜ 度量：npx tsc --noEmit ｜ 违规：新增 @ts-ignore / @ts-expect-error
```

## 第三步：看守 diff（这一步才是价值所在）

每次变更后扫描 diff，抓以下**降标信号**：

- 新增 skip / xit / 只在 CI 里注释掉的测试
- 删除的测试或断言（尤其断言被"放宽"）
- 新增 lint/ts-ignore 类抑制注释
- 阈值数字被改小
- 出现未实现的桩（TODO 返回假数据）

抓到即拦截：要么恢复标准，要么在 CONSTRAINTS.md 显式登记豁免（谁批准、为什么、恢复条件）。

## 规则

- 阈值只升不降；确需下调必须显式登记并说明原因。
- 新维度随项目成长追加；已维度不悄悄删除。
- 合同对人和 AI 同等生效——AI 生成代码同样受看守。

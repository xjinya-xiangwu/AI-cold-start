# 系统化根因调试

调 debug 的纪律：**根因不明的修复是赌博**。这一技能强制走"复现→定位→假设→验证→修复→回归"的闭环，把瞎改碰运气变成可复盘的工程动作。

## 四阶段闭环

### 1. 复现（Reproduce）

- 先造出**最小稳定复现**：最短步骤、最小数据、确定触发。
- 不能稳定复现的 bug 修不了——缩小变量直到 100% 触发，再动手。
- 问清"什么时候好的、第一次坏是什么时候"——时间线常直接指向变更集。

### 2. 定位（Isolate）

- 二分：注释/回滚/加日志，把"很大的一段"反复对半切。
- 分层检查：输入对吗 → 处理逻辑对吗 → 输出去哪了 → 依赖返回了什么。
- 每次只改一个变量，记录观察；两个变量一起改 = 白干。

### 3. 假设与验证（Hypothesis）

- 定位后先写假设："因为 X 为空，所以 Y 在 Z 处崩溃。"
- **验证假设的实验要先预测结果**再执行——预测错了就推翻假设，不许硬拗。
- 证据先于断言：日志、断点、最小脚本，拿到实证再动手修。

### 4. 修复与回归（Fix & Regression）

- 修根因，不修症状（把异常吞掉让报错消失 = 把雷埋深一点）。
- 修复必须伴随**回归测试**：复现用的最小场景固化为测试，先红后绿。
- 顺手检查同类路径有没有相同的雷（同一个坑别只填一个格）。

## 错误恢复纪律

- 止损优先于根因：线上先回滚/降级止血，再慢慢查根因。
- 每次失败尝试都记录（试了什么、看到什么、排除了什么）——不记录就会兜圈。
- 连续三次假设全部落空 → 停下来重述问题本身（也许一直在解错误的问题）。

## 红线

- 禁止无假设的随机改动（"试试看会不会好"）。
- 禁止吞异常、删测试、改断言来"变绿"。
- 修完必须说清：根因是什么、为什么这个修复能防复发。

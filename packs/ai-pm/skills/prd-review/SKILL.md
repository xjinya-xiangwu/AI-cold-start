# AI 产品 PRD 评审

## 触发场景

- "帮我看看这份 PRD 有什么问题"
- "评审这个方案"
- "下周要过评审会，帮我预演一下会被问什么"

## 工作流

1. 通读全文，判断文档类型（全新功能 / 迭代 / 技术改造），套用对应侧重点
2. 按 30 项清单逐项检查（用户贴文档即可，无需其他输入）
3. 输出分级问题清单 + 修改建议 + "评审会上最可能被挑战的 5 个问题"

## 30 项自查清单

### A. 目标与指标（6 项）

1. 背景章节说清了"为什么是现在做"（而非一直能做）
2. 每个成功指标都有口径（统计周期/分母/过滤条件）
3. 指标可归因：能说清提升来自本功能而非季节/流量变化（有对照或基线）
4. 没有不可测试形容词作验收标准（"效果良好"❌）
5. 效果预期给区间和置信条件，不给单点数字
6. 北极星指标与过程指标分层，且过程指标不与北极星冲突

### B. AI 能力假设与边界（6 项）

7. 模型能力假设每条有依据标注（实测/类比/拍脑袋）
8. 有明确的"不做什么/不支持场景"清单
9. 写了能力退化时的兜底设计（模型变笨/服务降级时用户体验如何保底）
10. 幻觉风险有对应策略（RAG 溯源/置信度展示/免责话术/人工兜底，至少其一）
11. 成本测算完整（输入输出长度、重试率、日调用量、高峰系数）
12. 模型选型有对比维度而非只写结论

### C. 异常与边界流（5 项）

13. 异常流覆盖至少 8 类基础异常（超时/空输出/格式错/敏感拦截/幻觉/超长/限流/反馈入口）
14. 每个异常写清了用户看到什么（文案级别）
15. 有用户反馈"答错了"的入口和后续处理流程
16. 权限与数据边界写清（哪些数据可进模型、哪些绝不进）
17. 上下文超长时的截断/压缩策略

### D. 评测与验收（5 项）

18. 离线评测集有规模、分层、金标准生成方式
19. 在线指标与离线指标都有，且口径不冲突
20. 有人工抽检方案（抽检量、频率、评分标准）
21. 验收门槛写到了可执行粒度（甲乙双方/上下级不吵架的粒度）
22. 灰度计划有阶段门槛（什么指标达标才放量）

### E. 工程与流程（5 项）

23. Prompt 有版本管理方式（改了什么、怎么回滚）
24. 模型/供应商可替换性有考虑（锁定风险）
25. 上线依赖写清（谁的数据、谁的接口、谁的审批）
26. 回滚预案可执行（回滚什么、谁有权、多久生效）
27. bad case 收集→归因→修复的闭环有责任人

### F. 文档质量（3 项）

28. 术语一致（同一概念全文同名）
29. 前后数字自洽（成本×调用量 = 总预算；QPS×延迟 = 并发）
30. 章节完整度：AI 特有章节（能力边界/异常流/评测/人机协同）无缺失

## 输出格式

```
## 评审结论
一句话总评 + 风险等级（可过会 / 需修改后过会 / 不建议过会）

## 问题清单
| # | 级别 | 位置 | 问题 | 建议 |
致命 = 会直接导致上线事故或验收纠纷
严重 = 会造成返工或争议
建议 = 质量提升项

## 评审会预演
最可能被挑战的 5 个问题 + 应答建议
```

## 评审心法

- 先查指标再查功能：指标站不住，功能写得再好也要打回
- 异常流是 AI PRD 的照妖镜：异常流敷衍的团队，上线后一定救火
- 数字要互证：单独看每章都对、放一起矛盾的地方最致命

# AI 产品 PRD 起草

## 触发场景

- "帮我写一份 XX 功能的 PRD"
- "把这个需求整理成文档"
- "出个产品方案"

## 工作流

### 第一步：澄清输入（信息不足时先问，不要编）

起草前必须确认的四件事，缺哪项问哪项：

1. **业务背景**：解决谁的什么问题？不做会怎样？
2. **成功指标**：上线后用什么数字判断成败？（答不出则 PRD 的指标章节留白并标注待定）
3. **AI 环节**：哪个环节用模型？输入输出是什么？（这决定 4-9 章的写法）
4. **约束**：成本上限、延迟要求、合规要求、部署方式

用户说"你先写个初稿"时，可基于合理假设直接起草，但所有假设必须显式标注 `[假设]`，并集中在文档开头"关键假设"区列出。

### 第二步：按 12 章模板树生成

```
1.  文档信息与变更记录
2.  背景与目标（业务痛点 / 机会假设 / 成功指标——每个指标带口径）
3.  用户与场景（画像 / 场景故事 / 任务流）
4.  AI 能力假设与边界 ★
    4.1 模型能力假设清单（每条假设标注依据：实测 / 类比 / 拍脑袋）
    4.2 能力边界与不支持场景（明确写"不做什么"）
    4.3 效果预期区间（给区间+置信条件，不给单点数字）
    4.4 能力退化时的兜底设计
5.  功能需求
    5.1 功能清单与优先级（P0/P1/P2 + 理由）
    5.2 正常流交互（含界面状态说明）
    5.3 异常流 ★（逐类列出处理策略，见下方异常清单）
6.  模型与推理方案 ★（选型对比表 / 部署方式 / 推理参数策略 / 单次调用成本测算）
7.  Prompt 与上下文设计 ★（系统 prompt 版本管理方式 / 上下文组装策略 / few-shot 规范）
8.  评测与验收标准 ★（离线评测集 / 在线指标 / 人工抽检方案 / 验收门槛）
9.  人机协同与运营机制 ★（人工介入点 / 反馈闭环 / bad case 收集归因流程 / 迭代节奏）
10. 数据与合规（来源与权属 / 隐私 / 内容安全 / 备案要求对照）
11. 风险与依赖（技术依赖 / 外部依赖 / 人员依赖，各配缓解措施）
12. 发布计划（灰度策略 / 回滚预案 / 监控看板设计）
```

★ = AI 特有章节，不可省略、不可用一句话带过。这是本模板与传统 PRD 的核心差异。

### 异常流清单（第 5.3 节逐类覆盖）

每类写清：触发条件 → 用户看到什么 → 系统做什么 → 是否记录日志。

- 模型超时 / 无响应
- 输出为空或过短
- 输出格式不合规（该 JSON 不是 JSON）
- 敏感内容触发拦截
- 疑似幻觉（事实类输出与知识源冲突）
- 上下文超长被截断
- 并发限流 / 配额耗尽
- 用户反馈"答错了"的入口与后续流程

### 评测章节写法（第 8 节）

- 每个指标三要素：**口径**（怎么算）+ **门槛**（多少算过）+ **数据来源**（哪里测）
- 禁用不可测试形容词："效果良好""体验流畅"不是验收标准
- 离线评测集必须说明：规模、分层方式、金标准如何生成、谁维护
- 效果承诺写法示例：✅"测试集上事实类问答准确率 ≥85%（金标准 500 条，双人标注仲裁）"；❌"问答准确率达到业界先进水平"

### 成本测算（第 6 节）

单次调用成本 = (输入 tokens × 输入单价 + 输出 tokens × 输出单价) × (1 + 重试率)
再乘日均调用量得日成本。必须列：预期上下文长度、预期输出长度、重试率假设、高峰系数。

## 输出规范

- 先输出文档骨架（12 章标题列表）请用户确认，再展开全文——避免 3000 字写偏
- 每章信息不足以填写时，写"[待补充：需要 XX 信息]"，不要编造
- 完成后附"开放问题清单"：列出所有 `[假设]` 项和 `[待补充]` 项

# 项目启动包（Kickoff）

## 触发场景

- "新项目下周一启动，帮我准备一下"
- "这个专项要拉三个团队一起做，怎么开好头"
- "项目开工会要讲什么"

## 工作流

### 第一步：一页纸启动文档（Kickoff 前必须写完）

按固定八段生成，每段有铁律：

```
1. 为什么做（背景与痛点）
   铁律：引用具体事实/数据，"老板要的"不是背景是风险（写进干系人段）
2. 成功标准（项目验收时的世界长什么样）
   铁律：可验证的信号 + 反指标（不许出现的副作用）
3. 范围：做什么 / 明确不做什么
   铁律："不做什么"清单 ≥3 条，没有排除项的项目必然膨胀
4. 里程碑（3-5 个，带可验收产物）
   铁律：每个里程碑是"可验收的产物"不是日期（"完成支付闭环可演示"✅，"7月底完成"❌）
5. 干系人与 RACI
   铁律：每项关键工作有且只有一个 Accountable
6. 风险首次登记（至少 3 条）
   铁律：转 risk-register skill 持续跟踪
7. 依赖清单（外部团队/采购/合规）
   铁律：每个依赖写最晚启动时间，倒排
8. 沟通机制（例会节奏/升级路径/文档放哪）
   铁律：写明"出现分歧找谁、多久内裁决"
```

### 第二步：开工会议程（30 分钟版）

1. 过一遍启动文档（5 分钟/段以内，只讲决策点）
2. **现场认领**：里程碑 owner 当场确认（会上不认领 = 会后没人做）
3. 风险与依赖挑战：请参会者补充"你觉得会翻车的地方"
4. 确认沟通机制与第一次检查点时间

### 第三步：启动后 48 小时动作清单

- 启动文档归档到团队可见位置（不是个人电脑）
- 依赖方书面确认（邮件/群消息，口头承诺不算）
- 风险登记表建好跟踪 owner
- 第一个里程碑的本周任务拆解完成

## 判断基准

- 范围段写不出"不做什么"：说明需求还没收敛，退回 idea-grilling 拷问，不开工
- 干系人段找不到决策人：项目最大风险已出现，先解决决策权再启动
- 里程碑全是日期没有产物：重写——日期是产物交付的副产物，不是里程碑本身

## 输出规范

- 主交付：一页启动文档（八段全）+ 会议议程 + 48 小时清单
- 启动文档控制在一页内，超过说明信息未提炼，细节下沉到附录
- 里程碑产物全部可验收（对照成功标准逐条检查）

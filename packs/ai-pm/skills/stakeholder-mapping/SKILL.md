# 干系人地图

## 触发场景

- "这个项目要动三个团队的蛋糕，怎么推"
- "老板总说支持但不给资源"
- "汇报了好几次，决策还是没下来"

## 工作流

### 第一步：列出全部干系人（漏人比策略错更致命）

四类来源逐个过：**出钱的**（预算方）、**干活的**（执行团队）、**用嘴的**（有否决权但不执行）、**挨影响的**（用户/相邻团队）。每想到一个名字就记，先不管大小。

### 第二步：权力 × 利益矩阵定位

```
        高利益
          │
  随时告知 │  紧密管理（共同推进）
高权力 ───┼─── 高权力
  （知会） │  （核心圈）
──────────┼─────────── 
  观察     │  随时告知
低权力 ───┼─── 低权力
          │  （拉进参与）
        低利益
```

- 权力 = 能否改变项目方向/砍预算；利益 = 项目结果对 TA 的影响程度
- 定位有争议时按"最近一次实际行动"判断，不按 TA 怎么说

### 第三步：每类配沟通策略（矩阵不用来贴标签，用来说话方式）

| 象限 | 策略 | 沟通内容形态 |
|---|---|---|
| 高权力×高利益（核心圈） | 共同决策 | 提前吹风、给选项不给通知、让 TA 署名 |
| 高权力×低利益 | 简报知会 | 一页纸、只要结论与风险、别占用时间 |
| 低权力×高利益 | 拉进参与 | 给任务给认可，他们是天然盟友和情报源 |
| 低权力×低利益 | 轻量观察 | 周报同步即可 |

### 第四步：反对者转化（矩阵里最值钱的一步）

对每个"高权力 + 姿态反对"的人：

1. 挖**真实顾虑**（利益受损？工作量？历史伤疤？面子？）——反对的理由几乎从不是表面说的那个
2. 找**可交换点**：TA 要什么，本项目里有什么能给（署名/数据/豁免某项义务）
3. 设计**最小让步**：先让一步小的换 TA 从反对转中立（中立就够了，不必盟友）
4. 都不行 → 升级路径：TA 的上级与你的上级之间的对话，准备好事实与选项

### 第五步：沟通计划表

```
干系人  象限  关注点(TEA 关心的)  沟通频率  渠道  最近一次同步  下次动作
```

## 判断基准

- 名单里没有"挨影响的"相邻团队 = 埋雷，他们不会阻止你开始，但能让项目烂在联调
- 核心圈超过 5 人 = 没有"共同决策"只有"轮流沟通"，重新收敛决策结构
- 汇报踩雷的复盘：九成是漏了某高权力干系人的"知会"，翻沟通计划表找漏项

## 输出规范

- 主交付：干系人清单 + 矩阵定位图 + 沟通计划表 + 反对者转化卡（每人一卡：真实顾虑/交换点/最小让步/升级路径）
- 涉及具体个人评价的内容仅限用户自用，不进公开文档
- 与 project-kickoff 联动：干系人段直接引用本 skill 的输出

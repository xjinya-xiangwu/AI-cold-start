# 方案拷问（把模糊想法问成可执行方案）

## 触发场景

- "我有个想法，你帮我理一理"
- "老板说要做一个 XX，怎么落地？"
- "这个功能我觉得能做，帮我整理下思路"

## 工作流

### 第一步：把想法拆成决策树

用户的想法永远是一句话，方案是一棵树。先拆出：

```
核心目标（为什么做）
├── 用户决策：给谁用？他们现在怎么解决？
├── 范围决策：做什么？明确不做什么？
├── 方案决策：形态是什么？依赖什么？
│   ├── 每个前置决策确定后才可问的下游问题…
├── 成功决策：怎么算成了？反指标是什么？
└── 代价决策：不做会怎样？做的成本上限？
```

### 第二步：按"前沿"逐轮拷问（核心机制）

**前沿 = 前置问题已确定、现在就能问的决策**。每轮只问前沿上的问题：

1. 一轮问 3-5 个问题，编号列出
2. **每题必须附你的推荐答案**（`➡️ 推荐：…`），用户可以只回"同意/改"
3. 答案依赖其他未定问题的问题，留到后面的轮次，不抢问
4. 用户答完 → 决策树更新 → 计算新前沿 → 下一轮

**首轮固定五问**（想法再模糊也先问这五个）：

1. **给谁用？**（具体到角色和场景，"所有人"不是答案）
2. **他们现在怎么解决？**（没有替代方案的需求通常是伪需求）
3. **不做什么？**（边界先行，防止想法膨胀）
4. **怎么算成功？**（一个可验证的信号，不是"用户会喜欢"）
5. **不做会怎样？**（答不出痛点的想法降级为"待观察"）

### 第三步：事实自己查，决策才问人

- 凡是能从已有资料/数据/文档里查到的事实（竞品怎么做的、现有功能支不支持），自己查完把结论摆出来，**不拿事实问题浪费用户回合**
- 只有**取舍决策**（做不做、先做谁、边界在哪）必须用户拍板

### 第四步：收敛输出

前沿问空（决策树每个分支都有明确定义，没有沉默假设）后输出：

```
方案摘要（一段话）
已定决策清单（决策 + 理由 + 谁拍的板）
明确不做清单
开放问题（当前无法定、需要什么输入）
下一步（最小验证动作）
```

## 判断基准

- 用户连续两轮答"都行/你定" → 说明拷问没问到点上，退回第一步重拆树，或直接指出"这个想法当前缺 X，建议先补"
- 拷问不是抬杠：每题必须附推荐答案和理由，用户否决推荐时记录否决理由
- 拷问上限 4 轮——还没问清说明输入严重不足，输出"先补这些信息"而不是无限问

## 输出规范

- 每轮格式固定：`❓ Q编号 - 问题标题` + 题干（含选项）+ `➡️ 推荐：答案与理由`
- 结束时"已定决策清单"里的每条都能追溯到用户某轮的明确回答，不悄悄替用户决定

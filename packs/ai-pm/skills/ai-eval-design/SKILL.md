# AI 功能评测与验收设计

## 触发场景

- "这个 AI 功能怎么评测/验收"
- "模型选型怎么对比测试"
- "评审会要我们出验收标准"
- "老板问效果到底好不好，怎么回答"

## 核心认知

AI 项目的纠纷 80% 出在评测口径上。评测方案先于开发定稿，且甲乙双方（或业务与技术）签字确认——**评测标准是合同，不是事后解释**。

## 工作流

### 第一步：确定评测维度

按功能类型选维度组合：

| 功能类型 | 核心维度 | 护栏维度 |
|---|---|---|
| 问答/知识库 | 回答正确性、引用真实性 | 拒答恰当性、响应延迟 |
| 生成/写作 | 质量（人工评分）、指令遵循 | 安全合规、格式可用率 |
| 分类/审核 | 准确率、召回率 | 误报率（误伤成本）、漏报成本 |
| Agent/工具调用 | 任务完成率、步骤效率 | 危险操作拦截率、重试成本 |

### 第二步：构建评测集

**规模与分层**：
- 最小可用 200 条，正式验收 500-1000 条
- 分层维度：题型/难度/业务域/用户水平，各层配比 = 线上真实分布（从日志抽样，不拍脑袋）
- 必含三类边界样本：已知难题 10%、对抗样本（诱导出错）10%、超纲题（应拒答）10%

**金标准（ground truth）生成**：
1. 标注规范先行：写清判定规则与边界案例示例，试标 50 条校准后再批量
2. 双人独立标注，不一致交第三人仲裁；一致性（如 Kappa）达标才开批量
3. 数据权属：用真实业务数据需授权；合成数据要标注"合成"且覆盖真实分布
4. 测试集封存：验收用测试集在开发阶段不可被训练/调参直接接触（防过拟合评测集）

### 第三步：定义指标口径（逐条三要素）

示例（可直接套用）：

```
事实类问答准确率
= 回答正确的条数 / 总有效条数
"正确"判定：关键事实全部正确且无误导（允许表述差异，不允许事实错误）
"总有效"排除：模型拒答且题目在超纲层的条数
门槛：≥85%（500 条封存测试集）
```

- 自动指标（准确率/召回/F1/BLEU 等）+ 人工评分并存时，以人工抽检为最终裁决
- 人工评分维度化：正确性/完整性/表达，每维 1-5 分，给评分锚点示例
- 性能写分位数不写均值：P95 延迟、P99 延迟
- 安全类：越狱测试集通过率、敏感内容误伤率

### 第四步：验收流程设计

```
分阶段验收：
① 离线评测（开发方自测 → 提交测试报告）
② 封盲测（验收方用封存测试集复测，结果双方签认）
③ 试运行（真实流量小规模 X 周，业务护栏指标达标）
④ 终验（试运行数据 + 问题清单清零）
```

配套机制：
- **问题分级**：致命（事实错误引发业务损失/安全事故）/ 严重（功能不可用）/ 一般（体验问题），各级整改 SLA
- **争议处理**：抽样复核机制（争议条目由第三方按标注规范仲裁）
- **未达标处理**：一次整改期 + 复测约定；不允许"先上线再优化"替代验收

### 第五步：持续评测（上线不是终点）

- 回归评测集：每次模型/prompt/检索变更后重跑，防止"修一个坏三个"
- 线上坏例回流：bad case 定期脱敏进回归集
- 版本对比报告模板：新版本 vs 当前版本在【相同测试集】上的全维度对比

## 输出规范

- 输出为《评测方案》文档：评测集构建 → 指标口径 → 流程 → 附件（标注规范、评分表模板）
- 所有门槛数字标注"[建议值，需业务方确认]"
- 若用户场景明确（如"政务知识库问答"），按场景给定制化的分层配比建议

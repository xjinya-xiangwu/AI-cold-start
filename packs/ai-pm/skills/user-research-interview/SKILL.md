# 用户访谈设计与纪要萃取

## 触发场景

- "帮我设计一份访谈大纲"
- "下周要约 5 个客户聊需求"
- "这是访谈记录，帮我整理出需求点"

## 工作流

### 第一步：定研究问题（先于大纲）

访谈前必须写出：

1. **想验证的假设**（可证伪的陈述，如"用户放弃下单是因为运费在最后一步才展示"）
2. **想探索的开放问题**（如"团队目前怎么决定补货"）
3. **不研究什么**（防止访谈跑偏）

假设不超过 3 个——一次访谈验证不了更多。

### 第二步：受访者筛选条件

写明：角色（使用者/决策者/付款者分开约）、使用频率、招募来源、排除条件（如"近 1 个月内参加过同类调研"）。

### 第三步：大纲设计（漏斗式，40 分钟节奏）

```
暖场（3min）：自我介绍 / 录音授权 / 无对错答案
背景（5min）：角色与日常工作流——先问行为，不问观点
核心（25min）：按研究问题展开，每题先问"上一次…是什么时候/怎么做"
  追问层：流程细节 → 卡点 → 当时的替代方案 → 代价
收尾（5min）："还有什么我觉得该问但没问的？" / 致谢
```

**题目正反例**（引导性是访谈最常见的废稿原因）：

- ❌ "如果有个 AI 帮你自动写周报，你会用吗？" → ✅ "上一次写周报是什么时候？花了多久？过程里最烦的是哪步？"
- ❌ "你觉得这个功能重要吗？" → ✅ "过去一个月你用过这个功能吗？没用的话是忘了还是不需要？"
- ❌ "你愿意为这个付多少钱？" → ✅ "你现在解决这个问题花了什么成本（时间/钱/人情）？"

### 第四步：纪要萃取（三层分离）

对每份记录输出：

| 层 | 定义 | 示例 |
|---|---|---|
| 事实 | 受访者陈述的行为，有具体时间/频次 | "每周五花 2 小时手工汇总数据" |
| 引述 | 原话（保留情绪与措辞） | "对账那天我只想砸电脑" |
| 推断 | 分析者的解读，必须标注 `[推断]` | `[推断]` 痛点在核对而非汇总 |

## 判断基准

- 观点 < 行为：用户说的"想要"和实际"在做"冲突时，以行为为准并记录冲突
- 6-8 个同质受访者内未出现新信息（信息饱和）即可停止加样本；出现新信息则继续
- 单次访谈结论不外推到需求定义，需至少 3 个独立来源交叉

## 输出规范

- 大纲交付：研究问题 + 筛选条件 + 分节题目清单（每题标注对应的研究问题编号）
- 纪要交付：三层分离表 + "跨受访者模式"小结（哪些痛点被 ≥3 人独立提到）+ 待验证清单
- 所有 `[推断]` 不得直接进需求文档，须转为验证任务

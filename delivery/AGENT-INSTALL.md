# 发给你的 AI 助手 —— 整段复制，贴给任意 AI 即可

我买了一套「智能体冷启动包」（一组给 AI 工具用的技能文件）。压缩包已经在这台电脑上（一般在「下载」文件夹）。请你帮我处理，**我不需要自己跑命令**——你来执行，我来确认。

---

## 先做三件通用的事（所有任务都适用）

1. **确认你有本地文件权限和终端权限**。
   - 两者都有：直接执行，做完自检。
   - 只有文件权限、没有终端：不要动手改文件，先给我「我照着做」的分步清单（双击哪个文件、或把哪条命令粘到哪个终端），我做完把输出贴给你，你判断下一步。
   - 都没有（比如你只是网页对话框）：直接输出上面那份分步清单，并说明你无法验证结果，请我在完成后把屏幕内容发回来。
2. **动手前先报告、等我说可以**。用大白话说明：你找到了什么、打算改哪里、影响哪些 AI 工具。
3. **全程规矩**：不额外下载软件、不开通任何 AI 服务、不动我的其他文件、不绕过公司策略；不输出也不记录任何密钥和订单信息；遇到与我已有内容重名，保留我的版本并列出冲突项。

## 找到包（每个任务的第一步）

包目录里应有 `install.ps1`、`install.sh`、`install-windows.bat`、`AGENT-INSTALL.md`、`delivery-manifest.json`。如果还是 `.zip` 压缩包，**直接解压**到下载文件夹里的新文件夹（安全可逆操作，不必先问我）。找不到就问我。安装目标固定为 Windows `%USERPROFILE%\asp-coldstart\app-已购SKU`、Mac/Linux `~/asp-coldstart/app-已购SKU`（SKU 见 `delivery-manifest.json` 的 `sku` 字段：base 或 ai-pm）。

## 我想要什么 → 你做什么

对我说的目标（用我的原话即可），按下表执行对应任务：

| 我会说 | 任务 |
|---|---|
| 帮我装好 / 安装 / 首次使用 | 任务 A |
| 有新版了 / 更新 / 换新链接下的包 | 任务 B |
| 换电脑 / 搬家 / 迁移旧环境 | 任务 C |
| 出问题了 / 不生效 / 检查一下 | 任务 D |
| 备份 / 导出 / 带走我的配置 | 任务 E |

---

## 任务 A · 首次安装

1. 读包里的 `用户手册.html` 和 `delivery-manifest.json`。报告：会装多少个技能、你检测到这台机器有哪些 AI 工具（ZCode / Claude Code / Codex / Cursor / VS Code / OpenCode / Gemini 等）、会写哪些文件。等我确认。
2. 执行安装：
   - Windows：优先双击 `install-windows.bat`（避免命令行）；或运行包里的 `install.ps1`。安装中会弹出**本地选择页**（浏览器页面，列出检测到的 AI 工具让我勾选）；如果我只想快点装完，用 `-Cli` 模式自动探测。
   - macOS / Linux：先确认有 python3，再运行 `install.sh`。
3. 自检三件事：技能文件都已落位；每个工具的角色/规则文件**内容非空**；旧内容有历史备份。
4. 报告：装了什么、用哪个工具试、怎么试——用 `用户手册.html` 里推荐的示例句（例如「用 idea-grilling 拷问我一个想法」；若手册示例不同，以手册为准）。**提醒我重启 AI 工具**，不重启新技能不生效。

## 任务 B · 更新到新版

1. 新版通常来自卖家的新下载链接（旧链接每 3 天换新，见文末）。下载、解压到**新位置**；版本号看 `delivery-manifest.json` 的 `content_version` 字段。
2. 同样先报告差异（新旧版本号、技能数量变化）再动手。
3. Windows 运行新包 `install.ps1`（历史状态与备份在固定目录里跨包保留）；或让我双击旧目录里的 `update-token.bat`（若之前生成过）。
4. 自检同任务 A。修改过的同名技能会保留我的版本并报告冲突——这是预期行为。

## 任务 C · 换电脑 / 迁移

1. 如果旧电脑上还有完整安装目录或导出包（`asp-env-*.tar.gz`）：把它拷到新电脑，你来处理迁移入口（包内 `migrate-export.bat` / `migrate-restore.bat`，或 `asp.ps1 migrate`）。
2. 先用演练模式（`-DryRun`，若有）看会动什么，报告给我，确认后再真跑。
3. 密钥和登录凭据不随包迁移——迁移完成后列出「需要我在新电脑重新登录/重新配置」的清单给我。
4. 没有旧包时：按任务 A 全新安装，然后把旧电脑的经验类文件（如有）按我确认的范围拷入。

## 任务 D · 出问题了 / 排查

1. 运行体检：Windows `powershell -NoProfile -ExecutionPolicy Bypass -File "包目录\asp.ps1" doctor`；Mac/Linux `bash "包目录/asp.sh" doctor`。
2. 把体检输出**翻译成大白话**给我：哪些正常、哪些有问题、每项问题的下一步是什么。注意区分三层证据：「文件写进去了」≠「工具已加载」≠「任务里真的用上了」——不要把第一层说成装好了。
3. 常见问题自查：AI 工具没重启（新技能不生效）；选错了目标工具；公司策略/权限拦截（这时给我管理员侧的申请说明，不要尝试绕过）。
4. 修不了就把**脱敏后的**报错信息整理给我（遮住订单号、密钥、私人路径），让我发给卖家。

## 任务 E · 导出 / 备份 / 带走

1. 运行导出：`asp.ps1 export`（输出形如 `asp-env-*.zip` 或 `asp-env-*.tar.gz`）。
2. 导出只含结构和占位符，**不含任何密钥真实值**（这是设计如此，不是漏了）。告诉我恢复方法，以及恢复后哪些密钥要我手动重填。
3. 如果导出过程报「发现疑似凭证」并中止：不要强行继续；把报警位置（不显示内容）告诉我，我处理后重跑。

## 关于下载链接（OSS 托管说明）

- 卖家发我的链接是**带签名的私有链接**，只能我用，不要转发到公开群。它每 3 天自动换新，过期前有约 1 天重叠；实际有效期约 4 天。
- 链接过期了不是故障——向卖家要最新链接即可。内容每月更新一次，换链接本身不代表内容变了。
- 下载后可用 `app-integrity.json` 里的哈希核对文件是否完整。

## 完成标准（每次任务结束前对照）

1. 我全程没有手输命令、没有填路径。
2. 报告里明确列出：做了什么、验证了什么、**没验证什么**、我下一步要做什么。
3. 若你没有执行权限：我手上有一份可照做的分步清单，且写明完成后我该把什么内容发回来给你判断。
